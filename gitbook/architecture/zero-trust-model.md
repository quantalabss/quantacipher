# Zero-Trust Security Model

In conventional enterprise cybersecurity, vendors frequently claim "Zero-Trust" while requiring you to transmit unencrypted plaintext payloads over TLS to their cloud Hardware Security Modules (HSMs) or hosted KMS clusters.

QuantaCipher is built on a **True Zero-Trust Architecture**. This guide details how the cryptographic boundary is enforced and why it is mathematically impossible for QuantaCipher's infrastructure to inspect or reconstruct your data.

---

## 1. The Architectural Flaw in Legacy Cloud KMS

In a typical cloud encryption architecture:

```
[Your Application] === Plaintext Over TLS ===> [Vendor Cloud KMS / HSM]
                                                      │
                                           (Decrypted in Vendor Memory)
                                                      │
[Your Database]    <=== Ciphertext Returned <=========┘
```

### The Inherent Vulnerabilities:
1. **Insider Threats & Subpoenas:** Cloud vendor engineers or lawful intercept warrants can compel disclosure of memory dumps or master keys.
2. **TLS Termination Exposure:** Plaintext exists in cleartext within the memory of the cloud KMS gateway before encryption occurs.
3. **Hardware Lock-In:** Organizations cannot migrate workloads without massive re-keying operations.

## 3. Mathematical Guarantees

### 1. Plaintext Never Leaves Local Memory
Whether running in Node.js, Next.js, Python, or a mobile browser, all plaintext reading, encryption, decryption, and signing operations occur strictly within the local process heap. At no point is plaintext serialized into an outbound HTTP request.

### 2. Zero Key Escrow
QuantaCipher does not manage, generate, store, or escrow your post-quantum private keys:
* In **Vault Mode**, the private key is created in volatile RAM and destroyed in under 2 milliseconds upon ciphertext generation.
* In **Secure Mode**, private keys are generated by your application and saved only in your own secure key management system (e.g., HashiCorp Vault, AWS Secrets Manager, or local encrypted disk).
* In **Signing Mode**, signing keys remain strictly in your custody.

### 3. Proof of Ignorance
Because the Gateway receives only the `QZ_...` ciphertext string, an adversary who compromises the QuantaCipher Gateway gains access only to random-looking ciphertext bytes. Without the client-held ML-KEM private key, reversing these ciphertexts requires breaking the hardness of the Module Learning With Errors (M-LWE) lattice problem.
