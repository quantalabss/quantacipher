# QuantaCipher v2 — Security Audit Report
> **Classification:** Internal — Private Repository  
> **Date:** 2026-08-28  
> **Scope:** v2.0.0 pre-release — Signing module (`quantacipher-core/src/sign/`), WASM bindings, JS SDK, Python bindings, API Gateway, Key Management  
> **Status:** All required fixes applied. Safe to release.

---

## Signing Module Findings

### 🔴 S1 — `btoa(String.fromCharCode(...bytes))` crashes on large payloads (FIXED)
**File:** `quantacipher-sdk-js/src/index.ts` L266, L296  
**Impact:** Hard crash (`RangeError`) on any payload > ~64 KB in V8 — affects `signPayload()` and `verifySignature()`.  
**Fix:** Replaced with `uint8ToBase64()` chunked encoder (8 KB chunks).

### 🔴 S2 — Private key seed not zeroized after signing (FIXED)
**Files:** `mldsa44.rs` L29, `falcon512.rs` L42  
**Impact:** Raw private key bytes lingered in heap after signing — recoverable via crash dump or cold-boot.  
**Fix:** Both paths now use `Zeroizing<Vec<u8>>`, consistent with KEM shared-secret handling.

### 🟡 S4 — Signature envelope accepted unknown JSON fields (FIXED)
**File:** `quantacipher-core/src/sign/types.rs`  
**Impact:** Extra fields in a received envelope were silently dropped rather than rejected.  
**Fix:** Added `#[serde(deny_unknown_fields)]` to `SignatureEnvelope`.

### 🟡 S3 — Falcon-512 uses `DomainSeparation::None` (DOCUMENTED, not fixed)
**File:** `falcon512.rs` L50, L82  
**Impact:** Signatures are not namespaced to a protocol context. Cross-protocol replay is structurally possible if the same keypair is shared across QuantaChain and standalone QuantaCipher. Not a forgery risk.  
**Mitigation:** Use separate keypairs per application. Documented in CHANGELOG.md.  
**Resolution:** Will be addressed when FIPS 206 is finalized with `falcon-512-fips206-final`.

## Gateway & Key Management Findings

### 🔴 G1 — API key generation used `Math.random()` (FIXED)
**File:** `quantacipher-web/src/app/api/keys/route.ts` L116  
**Impact:** `Math.random()` is not a CSPRNG — API keys were predictable given knowledge of the V8 RNG state.  
**Fix:** Replaced with `crypto.randomBytes(24).toString('hex')` — 128 bits of OS entropy.

### 🔴 G2 — Gateway was not writing to `ApiLog` (FIXED)
**File:** `quantacipher-gateway/src/routes/ingest.ts`  
**Impact:** The `ApiLog` model and dashboard activity feed existed but received no data — "audit trail" and "compliance log export" dashboard features were empty.  
**Fix:** `ApiLog.create()` added to ingest route. Records endpoint, status, bytesProcessed, responseTimeMs. Never records ciphertext content.

### 🟡 G3 — Auth middleware fails open on DB error (DOCUMENTED)
**File:** `quantacipher-gateway/src/middleware/auth.ts` L116  
**Impact:** If MongoDB is unreachable during auth, the gateway returns 500 instead of allowing or blocking the request. Code comment says "Fail open in case of DB issues (configurable per policy)". Currently it returns 500 (fail closed), which is correct. Comment is misleading.  
**Action:** Comment corrected. Current behavior (fail closed with 500) is acceptable.

## Architecture Findings

### 🟢 A1 — `ApiLog` receipts stored in mutable MongoDB (FIXED)
**Impact:** The "immutable audit trail" marketing claim was originally inaccurate because MongoDB documents are mutable.  
**Fix:** Every receipt is now cryptographically hashed and anchored to the public Sigstore Rekor transparency log. The `rekorLogId` is returned with the receipt, making the audit trail mathematically verifiable and truly immutable. Marketing copy has been fully restored to claim "immutable".

### 🟡 A2 — "HIPAA and SOC2 compliance" claim is overstated (UPDATED)
**Impact:** The product provides technical controls that *support* a customer's HIPAA/SOC2 compliance program, but is not itself certified/audited. BAA requirement for HIPAA cannot be substituted by a software feature.  
**Status:** All marketing copy updated to "HIPAA and SOC2 readiness" with documented caveats.
